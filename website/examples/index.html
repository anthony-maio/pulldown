Install and fetch the example

Use Python 3.10 or newer in a fresh virtual environment. Core extraction works without Chromium.

python -m pip install "pulldown==0.4.2"
pulldown get https://pulldown.making-minds.ai/examples/field-notes.html --detail structured --json-output --meta

Look for Release field notes, its section headings, and the service table summary. The JSON metadata explains which extraction strategy ran.

When the initial HTML is not enough

Open the JavaScript release board. Its three cards are inserted after the initial response. First fetch it over HTTP, then repeat with Chromium.

python -m pip install "pulldown[render]==0.4.2"
python -m playwright install chromium
pulldown get https://pulldown.making-minds.ai/examples/live-board.html --detail readable
pulldown get https://pulldown.making-minds.ai/examples/live-board.html --detail readable --render --wait 100

The HTTP result lacks the cards. The rendered result contains RENDERED-BOARD-READY and the Documentation, Search, and Export cards. Rendering bypasses the page cache so an earlier HTTP result cannot hide the new content.

Use the same page reader in Hermes

The native pulldown_fetch tool reads a public URL and returns Markdown, source metadata, and explicit truncation information. HTTP is the default; request rendering when the page needs JavaScript. It runs in its own Python environment.

The Hermes integration currently requires a source installation; the PyPI 0.4.2 commands above cover the existing CLI. Follow the Hermes installation and examples, then try the release board or an independent documentation page.

What this example establishes

All five modes work from the installed package, and Chromium retrieves content missing from the initial HTML. This is a repeatable fixture check. It does not establish extraction quality on every site, access to login-only content, or a token-saving percentage.

Private addresses are blocked by default. The local verification server requires an explicit override; these public example URLs do not. Browser rendering checks HTTP requests and blocks redirects, workers, and WebSockets. Use the final canonical URL when rendering. Ordinary HTTP fetching supports guarded redirects. These checks do not replace network isolation when processing untrusted sites.
