# Hermes plugin verification

Pulldown's native Hermes plugin passed installed-package, native-host, and
normal chat checks on 2026-10-29. This is a source delivery built locally from
the Hermes integration changes. The published PyPI 0.4.2 package predates the
integration; no new PyPI release was created by this check.

## Normal Hermes chat

The plugin was installed from the verified wheel in a separate WSL Python
environment and enabled with `hermes plugins enable pulldown`. Hermes reloaded
the plugin for new sessions. Its existing settings and tool selections were
preserved apart from adding Pulldown and explicitly withholding permission to
override built-in tools. The original configuration was backed up privately.

A normal chat discovered the tool and made three successful `pulldown_fetch`
calls: Python's asyncio documentation, the release board over HTTP, and the
same board with Chromium. The session exited with code 0 in 20.7 seconds. It
explained asyncio's intended use and API levels from the fetched page, cited
both source URLs, identified all three rendered cards with their statuses, and
qualified the board as fictional fixture data. None of those responses was
truncated.

This establishes the requested workflow on these pages. It does not establish
extraction quality on every website or access to authenticated content.

## Native host acceptance

`scripts/hermes-smoke.py` installed the same wheel's plugin into a disposable
profile and exercised the actual Hermes discovery and tool dispatcher. All
23 checks passed in 33.7 seconds, including both installation doctors, packaged
asset identity, runtime paths, preserved configuration, model tool exposure,
JSON dispatch, source metadata, profile caching, and tool removal on unload.

| Public source | Observed result |
|---|---|
| [Field notes](https://pulldown.making-minds.ai/examples/field-notes.html) | All expected headings; 2437 characters with routing metadata |
| Same article with `max_chars=1000` | 1000 characters; truncation explicit; original length reported |
| [Release board](https://pulldown.making-minds.ai/examples/live-board.html), HTTP | 390 characters; no rendered marker or cards |
| Same board with Chromium | 699 characters; marker plus Documentation, Search, and Export cards |
| [Python asyncio documentation](https://docs.python.org/3/library/asyncio.html) | 3863 characters; subject, async/await syntax, and API descriptions retained |
| Loopback URL | Rejected with `url_blocked` |

The native check used an isolated profile and left the active profile
unchanged. Enabling the live plugin happened afterward, as a separate step.

## Package and regression checks

The complete Windows suite passed 202 tests. New coverage includes plugin
registration and dispatch, argument validation, bounded output, child-process
timeouts, credential filtering, worker errors, installer ownership, real
symlink and junction checks, and preservation of configuration and user files.
No tests were skipped.

The sdist and wheel built successfully and passed Twine metadata checks.
`scripts/smoke-installed.py` installed the wheel into a fresh Windows environment
and verified all five existing extraction modes, metadata, MCP registration,
the bundled model, private-address rejection, real Chromium rendering, and
render redirect rejection. It also exercised plugin installation, doctor,
runtime binding, configuration preservation, and uninstall from the installed
CLI.

The audit reproduced a crawler robots.txt redirect bypass using mocked HTTP
responses. Both loopback and metadata-address regressions failed before the
fix and passed afterward. Public redirects still apply their robots rules,
and explicitly authorized local crawling still reads local rules. The Hermes
plugin exposes a single-page reader, not the crawler.

The worker limits returned content and process output and has a total deadline.
Pulldown's HTTP size check occurs after download; it is not a streaming memory
or network-transfer limit. Address checks also retain the documented DNS
limitations.

## Reproduce

Follow [the installation guide](../hermes.md), then run in the same OS as Hermes:

```sh
python3 scripts/hermes-smoke.py \
  --python /path/to/installed-pulldown/venv/bin/python \
  --hermes hermes \
  --hermes-source /path/to/hermes-agent \
  --profile-parent /path/to/hermes-home/profiles \
  --wheel /path/to/local-pulldown.whl \
  --output /tmp/pulldown-hermes-verification.json
```

The harness reuses the installed host's dependency runtime, disables lazy
dependency installation, and removes its disposable profile. Normal chat
verification uses the prompts in the installation guide and remains a
separate check from direct native dispatch.
